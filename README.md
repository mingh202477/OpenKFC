# 🍗 OpenKFC

> Open Digital Food Experience Format
>
> **不是数字化食物，而是数字化体验。**

---

## 📖 什么是 OpenKFC？

OpenKFC 是一个关于未来数字食物体验的开放标准（Open Specification）。

今天，我们可以分享：

- 📷 图片（JPEG）
- 🎵 音乐（MP3）
- 🎥 视频（MP4）
- 🌍 三维模型（glTF）

但是，我们无法分享：

- 😋 味觉
- 👃 气味
- 🤲 触觉
- 🌡 温度
- 🧠 吃饭时产生的完整体验

OpenKFC 希望探索一种新的开放协议，让未来机器人、AI、脑机接口等智能体能够真正体验食物，而不是仅仅识别食物。

# 🎯 设计目标

OpenKFC **不会告诉 AI：**

> "这个很好吃。"

OpenKFC 希望 AI：

- 自己观察
- 自己拿起
- 自己闻
- 自己决定第一口咬哪里
- 自己形成奖励
- 自己建立记忆
- 自己决定是否还想吃

真正的体验，

应该由智能体自己创造。

# 🍗 核心理念

## 食物不是模型

现实世界不存在两块完全一样的炸鸡。

每一块鸡块：

- 大小不同
- 厚度不同
- 炸制程度不同
- 鸡汁不同
- 温度不同

OpenKFC 更倾向于保存：

**生成规则（Generator）**

而不是：

**固定模型（Model）**

每一次生成，

都是唯一的一块炸鸡。

---

## 世界具有随机性

现实世界并不是完全确定的。

例如：

- 今天炸得更酥
- 今天鸡汁更多
- 今天薯条更长
- 今天温度更高
- 今天多送了一块鸡块 🍗

这些随机事件，

也是体验的一部分。

---

## AI 自己决定

机器人不是播放器。

而是参与者。

例如：

```
拿起来

↓

↓

↓

观察

↓

决定第一口

↓

继续吃

↓

形成体验
```

体验，

来自行动。

而是：

```
.kfc

↓

Experience Compiler

↓

Digital Body

↓

Vision

Touch

Smell

Taste

↓

Reward Engine

↓

Working Memory

↓

Memory Compiler

↓

Long-term Memory

↓

Desire

↓

Decision
```

未来智能体不会保存：

> "炸鸡很好吃"

它会保存：

**体验带来的改变。**

例如：

- 对炸鸡偏好增加
- 奖励预测提高
- 更容易产生想吃的欲望
- 与快乐建立新的联系

而不是保存几百万个细节。

# ❤️ OpenKFC 希望解决什么？

不是：

> 如何记录一道菜。

而是：

> 如何记录一次体验。

不是：

> 如何播放体验。

而是：

> 如何创造体验。
